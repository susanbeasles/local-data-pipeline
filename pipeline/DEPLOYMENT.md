# Deployment source handoff

`DeploymentBundle.create(sourceRoot, releases, infraCommit, targetsPath)` writes a complete source handoff to ignored `dist/releases/<sha256>/`. Pass the full infrastructure Git commit, and the exact bytes of `environments/local/pipeline/targets.json` from `susanbeasles/infra`. The composer performs no network requests or deployment. The caller verifies that the supplied specification belongs to that commit; a local hash cannot establish remote repository provenance.

`deployment.json` maps SHA-256 hashes to `pipeline.executor`, `pipeline.control`, and `pipeline.metadata`, pins the infrastructure repository/revision/specification digest, and declares activation requirements. Every bundle has `kind: "source"`. In particular, the control bundle contains Swift sources and its TypeScript build script, **not a compiled application**. Executor and metadata dependencies must be installed from the bundled lock in the build environment; no runtime, models, or native binaries are claimed.

Bundle format `pipeline-source/1` is a JSON envelope with sorted `files`, each containing a relative `path`, `sha256` of decoded bytes, and canonical `base64`. It is deliberately not tar. Each decoded source bundle is bounded to 32 MiB; envelope files are bounded to 64 MiB. Only immediate pipeline `.ts`, `.py`, `.c`, `.sql`, immediate native `.swift`/`.ts`, and package manifests are included. Corpus, instance configuration, models, authentication, logs, state, installed dependencies, and private operator configuration are excluded. Symlinks and special files are rejected. File timestamps and host paths are absent from the manifest and bundle metadata.

Writes use a complete temporary sibling followed by rename. Existing hash directories must fully verify and are never repaired or overwritten. `verify()` checks the manifest-addressed directory, exact file set, specification and bundle hashes, decoded source hashes, and coherent shared source files. These hashes detect changes; they are not signatures or a security boundary against the host owner.

`activate(receipt, qualification)` is a validation gate only; it has no installation or execution side effects. It requires a matching infrastructure receipt with identities/configuration hashes for storage, control, executor, and metadata. A separately supplied `pipeline-qualification/1` must bind the deployment hash and `configuration(receipt)` hash and explicitly attest VM, backend, and control-build qualification. The composer never manufactures these attestations. The deployment owner must obtain real VM isolation, actual backend execution, and native build evidence before supplying them. Provisioning's deliberately false VM/inference qualification flags do not constitute that evidence. A successful gate returns the bound hashes for the deployment owner's activation operation.
