# Native data workspace implementation plan

> **For agentic workers:** Use the existing design and test workflows. Implement independent services concurrently, then integrate and verify them in the native app.

**Goal:** Make sources, data review, ETL revisions and scoped CLI assistance first-class native controls.

**Architecture:** Reuse existing pipeline controls. Add a read-only Catalog, a versioned Dataset store, and independent agent Sessions. Integrate them through a frozen studio CLI bridge and modular SwiftUI views.

**Tech Stack:** Node 24, TypeScript, SQLite, SwiftUI/AppKit, installed Codex/Claude executables.

**Spec:** docs/superpowers/specs/2026-10-14-studio-design.md

## Global constraints

- Raw data and active collectors are read-only to this work; no production enrichment or model calls during engineering.
- All data/operator state stays outside Git. Explicit configuration resolves paths relative to its file.
- Retain macOS native UI and existing immutable execution controls.
- All new application logic is TypeScript; no runtime dependency installation.

## Review focus

- Stale snapshots or reused PIDs must not look like active collection.
- Missing/changed mirrors must be distinguished from valid SQLite records.
- Data edits, filtered records and validation failures need durable attributable dispositions.
- Context for field help must not accidentally include full datasets or previous conversations.
- Restarted agent/ETL workers must retain state without silently repeating completed work.

## Tasks

- [ ] Catalog: configurable registrations, read-only tables/records, actual JSONL comparison, metric provenance/freshness; synthetic corrupt/missing/source-change tests.
- [ ] Dataset: immutable revisions, annotations/links/search, JSON transforms/validation and checkpointed recovery; synthetic failure/correction/resume tests.
- [ ] Sessions: installed CLI adapters, bounded context packets, independent streamed sessions and explicit lifecycle actions; fake CLI subprocess tests, no live model requests.
- [ ] Studio bridge and native app: source cards, paged side-by-side explorer, revision/flow controls, help sheets and session UI; preserve processing controls.
- [ ] Integrate: test cross-service workflow, compile native application, freeze new control-plane release, register local sources without altering active processing releases; operator documentation and verified limitations.
