# Scoped CLI sessions

`pipeline/sessions.ts` launches installed Codex or Claude CLI processes only after an explicit application action. Engineering tests use synthetic executable fixtures; no provider inference or production dataset is part of verification.

`assist(packet)` returns the previewable operational metadata packet, an initial prompt, and exactly three suggested follow-up questions. Supported packet keys are `project`, `purpose`, `dataset`, `run`, `field`, scalar `value`, `definition`, `observedAt`, `age`, `provenance` (`source`, `location`, `observedAt`), and `controls`. Extra keys are discarded. Objects and arrays are rejected as field values. Source contents and earlier conversations are never discovered or attached automatically. A caller must preview and explicitly authorize any raw-record prompt through its own sharing flow.

Each initial help action starts a fresh provider session. `send(id, prompt)` resumes only that session's retained native provider ID. A second turn while running is rejected. Prompts travel over stdin, never shell interpolation or process arguments. Each complete initial prompt (scope, metadata, and user instructions) has a 12,288-byte UTF-8 budget; oversize input is rejected before launch. Values and metadata strings are individually bounded at 2,048 bytes.

`Sessions(root, providers, options?)` stores operator state beneath the supplied root. Options are `protectedRoots`, `readRoots`, `maxMillis` (default 30 minutes per provider turn), and `killMillis` (default 250 ms before escalation). Roots must be absolute. State storage must be disjoint from protected sources, including aliases. Every session has its own workspace, private atomic metadata, and append-only JSONL event log. Workers detach from the UI process. A SQLite transaction serializes control actions across processes and releases automatically when the controller exits. Worker identity requires its exact script, workspace metadata path, and random ownership token in the observed process command. Providers have separate process groups. Stop, output bounds, and deadlines signal only a verified owned provider group, then escalate to SIGKILL if it ignores SIGTERM. The worker remains available to publish the final error. Recovery retains provider identity for a later explicit follow-up.

`snapshot(id, offset=0)` returns `{session, offset, more, messages, events}`. Offsets count complete JSONL bytes, and messages/events contain only the requested page. Continue from the returned offset while `more` is true. Pages are at most 256 KiB; provider event lines are at most 128 KiB. Sessions stop accepting provider output or new turns near the 8 MiB durable log limit. Metadata exposes worker/provider PIDs, process status, turn number, provider session ID, workspace, timestamps, errors, parent session, operation, and generated summary.

Conversation controls preserve the original session:

- `reset(id)` stops active work and starts a fresh session with the original instructions and scoped context.
- `branch(id, prompt?)` uses Codex's installed `exec fork` support and a fresh application workspace. It requires a retained native provider ID.
- `rewind(id, turn)` starts a fresh provider session from the local transcript prefix through that turn. This is an application transcript branch, not deletion or native provider rollback. Prefixes beyond the initial prompt budget are rejected; compact first.
- `compact(id)` explicitly sends the scoped transcript to a separate summarization turn. Long transcripts use a visibly marked excerpt containing their beginning and end; omitted middle history remains in the original local log. On success the summary is exposed and the summarizer's native session ID is cleared. The next `send` starts a fresh provider session containing only scoped metadata, the generated summary, and that new prompt. Summaries over 6 KiB fail visibly and preserve the original.

Codex initial turns use `exec --json --skip-git-repo-check -`; follow-ups use `exec resume --json --skip-git-repo-check <provider-id> -`; branches use `exec fork`. Global `--cd` and `--sandbox` options apply to every turn. Help and summaries select `read-only`; collection selects `workspace-write` with additional writable roots cleared. Existing user configuration, rules, authentication, and approval controls remain in effect. No provider is installed, no bypass flags are used, and no global configuration is edited. These command forms were checked against the installed CLI's help, consistent with [OpenAI's non-interactive mode documentation](https://developers.openai.com/codex/noninteractive/).

On macOS an additional `sandbox-exec` boundary covers the CLI, hooks, and child processes. File reads are denied by default and allowed for the session workspace, specified system runtime directories, the installed executable, and isolated native state. Global rollout history and arbitrary home/project files are excluded. Collection sessions may additionally read only explicit `readRoots`; help and summary turns ignore those approvals. `protectedRoots` deny reads for help/summary and deny writes in every mode, including approved collection sources. Writes are limited to the workspace, `/dev`, and isolated native state. `TMPDIR` is workspace-local. Environment inheritance is restricted to runtime, proxy and native provider authentication variables. Network access remains available for the selected provider. Other platforms fail closed until an equivalent read boundary is implemented.

Each fresh session copies only bounded regular native auth/config/instruction files and execution policy rules into a private native directory. Those snapshots are not provider-writable; global configuration is never written. Global history, skills, plugins, and unrelated sessions are not copied. Resume retains only this application's native session state. An explicit native branch copies only its selected application's parent state, and permits read access to that parent state for native absolute rollout references. Summary continuation uses another fresh native directory. Configurations that depend on unavailable guard files, unsupported runtime locations, or unrefreshable credentials can fail closed; authenticated provider startup has not been exercised here.

Before any Codex prompt is sent, `mcp list --json` runs inside that boundary. Server names are parsed privately; transport/config/secret values never enter application events. Every discovered MCP server is disabled through a per-invocation `mcp_servers.<name>.enabled=false` override, and a second list verifies that no server remains enabled. Malformed lists, unrecognized names, failed probes, or ineffective overrides block launch. The registry and user configuration remain unchanged. This restriction applies to metadata and collection sessions; collection work can use the provider's confined local tools.

Availability checks execute only installed binary help. Claude metadata assistance requires verified streaming, resume, and tool-restriction options, and runs with built-in tools disabled. Claude collection remains explicitly unavailable until its installed filesystem isolation has been verified. Native Claude branch is unavailable; transcript rewind and application compaction remain supported when metadata assistance is available. Missing binaries are reported without installation. Actual authenticated provider calls and live-provider GUI behavior were not exercised by these synthetic tests.
